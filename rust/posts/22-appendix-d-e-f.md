# 22. 부록 D-F와 다음 학습 경로

부록 D-F는 "학습 종료"가 아니라 "지속 가능한 실력 유지"를 만드는 구간입니다.
도구 체인, 에디션 이해, 커뮤니티 활용 루프를 갖추면 혼자서도 꾸준히 성장할 수 있습니다.

## 핵심 개념과 원리

### 1) 도구를 품질 게이트로 사용

- `rustfmt`: 스타일 일관성
- `clippy`: 잠재 버그/안티패턴 탐지
- `miri`: UB(정의되지 않은 동작) 탐색

도구는 "나중에"가 아니라 개발 루프에 항상 포함해야 효과가 큽니다.

### 2) 에디션은 언어 진화 단위

Rust 에디션(2018, 2021, 2024)은 기존 코드를 최대한 깨지 않으면서
새 문법/개선점을 도입하는 메커니즘입니다.

### 3) 학습 경로는 프로젝트 중심으로

문법 복습만 반복하면 실력이 정체됩니다.
작은 프로젝트를 계속 만들고, 레퍼런스/커뮤니티 피드백을 받는 루프가 중요합니다.

## 기술적인 심화 설명

### clippy 경고 정책

초기에는 경고를 참고만 하다가,
점진적으로 `-D warnings`로 강화하면 품질 기준을 올릴 수 있습니다.

### 에디션 업그레이드 전략

한 번에 대규모 변경보다,
`cargo fix` + 테스트 통과를 반복하며 단계적으로 올리는 것이 안전합니다.

### 학습 소스 우선순위

1. 공식 문서(Rust Book, Reference)
2. 표준 라이브러리 docs
3. 커뮤니티 글/영상

정보 신뢰도 순서를 지키면 시행착오가 줄어듭니다.

## 대표 코드

```bash
cargo fmt -- --check
cargo clippy -- -D warnings
cargo test
```

```toml
[package]
edition = "2024"
```

## 실습 문제 (3단계)

### 1) 기본

현재 프로젝트에 `fmt`, `clippy`, `test`를 순서대로 적용하고 결과를 기록.

### 2) 응용

에디션 변경 전후 컴파일/테스트 결과를 비교하고 차이를 정리.

### 3) 도전

4주 학습 루프를 설계: 주별 프로젝트 1개 + 회고 + 개선 계획.

## 장 특화 실습 정답

### 기본 정답 예시

```bash
cargo fmt -- --check
cargo clippy -- -D warnings
cargo test --workspace
```

### 응용 정답 방향

에디션 변경 후에는 반드시 lint/test를 재실행하고,
경고/오류를 분류해 자동 수정 가능한 항목부터 처리합니다.

### 도전 정답 예시(학습 루프)

1주차: CLI 도구 개선
2주차: HTTP API 미니 서버
3주차: 동시성 작업 큐
4주차: 리팩터링 + 문서화 + 성능 측정

## 오답 예시 3종 + 해설

### 오답 1) 도구를 릴리스 직전에만 실행

문제점: 누적된 경고/오류를 한 번에 처리해야 해서 비용이 폭증합니다.
개선: 커밋 전 루틴으로 자동화하세요.

### 오답 2) 에디션 변경을 "의미 없는 숫자 업데이트"로 처리

문제점: 변경 영향 분석 없이 진행해 숨은 호환성 이슈를 놓칠 수 있습니다.
개선: 변경 전후 검증 로그를 남기세요.

### 오답 3) 자료를 무작위로 소비

문제점: 지식이 파편화되고 실전 적용이 느립니다.
개선: 프로젝트 목표를 먼저 정하고 필요한 문서를 역으로 찾으세요.

## 완주 이후 추천 경로

1. `tokio` 기반 비동기 서버
2. `axum`/`actix-web` 백엔드 실전
3. `sqlx` + 트랜잭션 설계
4. 프로파일링/벤치마크 기반 성능 개선

## 미니 퀴즈 (정답 포함)

1) `fmt -> clippy -> test` 루프를 습관화해야 하는 이유는?
- 정답: 스타일/잠재 버그/동작 검증을 빠르게 반복해 품질 문제를 초기에 차단할 수 있기 때문입니다.

2) 에디션 업그레이드 시 가장 안전한 접근은?
- 정답: `cargo fix`와 테스트를 반복하며 단계적으로 변경 영향을 검증하는 것입니다.

3) 학습 정체를 피하는 가장 좋은 방법은?
- 정답: 문법 암기보다 작은 프로젝트를 계속 만들고 회고-개선 루프를 돌리는 것입니다.

## 학습 완료 기준

1. fmt/clippy/test 루프를 일상 개발에 고정한다.
2. 에디션 업그레이드 절차를 단계적으로 적용한다.
3. 프로젝트 중심 학습 루프를 스스로 설계한다.

## 실전 확장 미션

1. 4주 학습 로드맵 실행 후 회고 작성
2. 새 크레이트 도입 평가 체크리스트 만들기

## 부가 설명: 완주 이후 성장 속도를 결정하는 습관

Rust 실력은 새 문법을 얼마나 아느냐보다, 품질 루프를 얼마나 꾸준히 돌리느냐에서 갈립니다.
`fmt/clippy/test`를 일상화하면 작은 결함을 초기에 제거해 장기 생산성이 크게 올라갑니다.

또한 학습 로드맵은 고정 계획이 아니라 실험 기록입니다.
매주 "무엇을 만들었고 무엇이 막혔는지"를 남기면 다음 분기 학습 방향이 훨씬 선명해집니다.

## 아주 사소한 것까지: 용어 미니 사전

1. rustfmt: 코드 포맷터입니다.
2. clippy: 정적 분석 린터입니다.
3. miri: UB 탐지 실행기입니다.
4. edition: 언어 개선을 묶은 버전 단위입니다.
5. cargo fix: 자동 리팩터링/수정 보조 명령입니다.

## 10분 완독 보강: 심화 확장 본문

### 1) 실무 시나리오로 다시 보는 도구체인 루틴

이 장을 실무에 가져가면 가장 먼저 부딪히는 문제는 "예제에서는 단순했는데 실제 요구사항에서는 경우의 수가 훨씬 많다"는 점입니다.
그래서 개념을 외우는 방식보다, 입력 경계와 상태 전이를 먼저 표로 정리한 뒤 코드를 작성하는 방식이 훨씬 효과적입니다.
특히 변경 요청이 들어왔을 때 어떤 부분이 안전하게 확장 가능한지 확인하려면, 지금 장에서 다룬 핵심 개념을 모듈 경계와 함수 시그니처에 명시적으로 남겨 두어야 합니다.

### 2) 설계 트레이드오프: 에디션 업그레이드를 어디까지 강하게 가져갈 것인가

초보 단계에서는 "정답 패턴"을 그대로 쓰는 것이 좋지만, 중급 이후에는 항상 트레이드오프를 함께 봐야 합니다.
검증을 강하게 할수록 안전성은 올라가지만 코드량과 초기 진입 비용이 늘 수 있고, 반대로 빠른 구현을 택하면 단기 속도는 올라가지만 나중 수정 비용이 커집니다.
이 장에서는 안전성/가독성/성능 중 무엇이 현재 맥락에서 우선인지 먼저 정하고, 그 기준에 맞게 구현 강도를 선택하는 훈련이 중요합니다.

### 3) 디버깅 관점: 지속 학습 시스템에서 자주 생기는 실패 패턴

실패는 보통 "핵심 로직"이 아니라 경계에서 발생합니다. 입력 정규화 누락, 상태 전이 누락, 예외 경로 미처리, 로그 문맥 부족이 대표적입니다.
디버깅 속도를 높이려면 함수 단위로 사전조건/사후조건을 짧게라도 적어 두고, 실패 시 어떤 신호를 남길지(에러 타입/로그 키)를 미리 정해 두는 것이 좋습니다.
또한 동일한 문제를 반복하지 않기 위해, 이번 장에서 나온 오답 패턴을 개인 체크리스트로 변환해 다음 구현 전에 빠르게 점검하는 습관을 추천합니다.

### 4) 고급 숙련자 관점: 품질 자동화를 팀 규칙으로 고정하기

개인 실력은 반복으로 올라가지만, 팀 생산성은 규칙으로 올라갑니다.
이 장의 핵심 개념을 팀 규칙으로 만들려면 "코드 리뷰에서 무엇을 반드시 확인할지"를 명문화해야 합니다.
예를 들어 경계 입력 검증, 실패 모델 분리, 모듈 의존 방향, 테스트 최소 세트 같은 항목을 PR 체크리스트에 넣으면 품질 편차가 크게 줄어듭니다.
결국 고급 숙련자는 혼자 잘 짜는 사람을 넘어, 팀 전체가 같은 품질 기준으로 개발하도록 구조를 만드는 사람입니다.
